تاريخ التنفيذ: 2026-10-19 — بيئة الاختبار: Linux (Ubuntu 24.04)، Rust 1.97، Node 22.
اختبارات Windows (بناء + `cargo test`) تُنفَّذ آليًا في GitHub Actions عند كل `push`.

## أهم ما تتحقق منه الاختبارات

**التشفير والاستمرارية**
- ملف قاعدة البيانات لا يبدأ بترويسة SQLite ولا يحتوي اسم المنشأة أو اسم المستخدم كنص مقروء.
- فتح القاعدة بمفتاح خاطئ يُرفض.
- بيانات المنشأة تبقى بعد إغلاق القاعدة وإعادة فتحها (محاكاة إعادة تشغيل البرنامج) + `integrity_check` و`cipher_integrity_check`.
- لا يُنشأ مفتاح جديد إذا وُجدت قاعدة بيانات وفُقد مفتاحها.

**الأمان**
- كلمة المرور مخزنة كـ Argon2id فقط؛ الأملاح فريدة.
- رسالة واحدة لكلمة مرور خاطئة ولمستخدم غير موجود؛ القفل بعد 5 محاولات حتى مع كلمة المرور الصحيحة.
- الإعداد الأول يُنفذ مرة واحدة فقط، ولا يُكتب شيء إذا فشل التحقق.
- الكاشير لا يملك صلاحية تعديل المنشأة؛ الجلسات تنتهي بالخمول وبتسجيل الخروج.
- سجل التدقيق يرفض UPDATE/DELETE، واكتشاف التلاعب حتى عند تجاوز الحماية بإسقاط الـ Trigger.
- المهاجرات: تطبيق متكرر آمن، واكتشاف تعديل مهاجرة منشورة.

**المحاسبة**
- قيد متوازن يُرحَّل ويحدّث الأرصدة؛ ميزان المراجعة متوازن دائمًا.
- قيد غير متوازن لا يُحفظ — حتى عند الكتابة المباشرة بـ SQL متجاوزًا التطبيق.
- الترحيل ذري: فشل سطر واحد يلغي القيد كاملًا ولا يستهلك رقمًا تسلسليًا.
- منع ترحيل المستند نفسه مرتين.
- منع تعديل أو حذف القيد المرحّل وأسطره أو إضافة أسطر إليه.
- القيد العكسي يصفّر الأثر، ولا يمكن عكس القيد مرتين.
- منع الترحيل لفترة مقفلة أو تاريخ خارج الفترات، ومنع تداخل الفترات.
- 50 قيدًا بمبالغ بالهللات: الترقيم متسلسل دون فجوات والميزان متوازن.
- المبالغ: لا انجراف عشري (0.1 + 0.2 = 0.30 تمامًا)، ورفض أكثر من خانتين عشريتين.

## اختبار يدوي للتطبيق الفعلي (نافذة سطح المكتب)

شُغّل البرنامج المبني كنافذة سطح مكتب على شاشة افتراضية، وتم التحكم به آليًا (لوحة مفاتيح وفأرة):

1. أول تشغيل ← معالج الإعداد بالعربية ✅
2. رقم ضريبي خاطئ ← رسالة عربية واضحة تحت الحقل ✅
3. كلمة مرور تحتوي اسم المستخدم ← رفض برسالة عربية ✅
4. إنهاء الإعداد ← شاشة الدخول مع رسالة نجاح ✅
5. كلمة مرور خاطئة ← «اسم المستخدم أو كلمة المرور غير صحيحة» ✅
6. دخول صحيح ← لوحة التحكم (بيانات توضيحية معلنة، حالة التشفير SQLCipher 4.14) ✅
7. تعديل بيانات المنشأة وحفظها ← تحديث الشريط العلوي ✅
8. إغلاق البرنامج وإعادة فتحه ← البيانات المعدّلة والوضع الداكن محفوظان، ولم تُطبق المهاجرات مرة ثانية ✅
9. سجل التدقيق يعرض العمليات وسلسلة التجزئة «سليمة» ✅
10. فحص ملفات القاعدة على القرص (`.db` و`.db-wal`) ← لا نص مقروء ✅

لقطات الشاشة في [`docs/screenshots`](screenshots).
