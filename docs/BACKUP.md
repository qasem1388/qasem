# النسخ الاحتياطي والاستعادة

## ما الذي يجب نسخه؟

| العنصر | المحتوى | الأداة |
|---|---|---|
| **قاعدة البيانات** | كل المحتوى والإعدادات والمستخدمين والرسائل وطلبات العروض والتوظيف وسجل العمليات | `scripts/backup.sh` |
| **الملفات المرفوعة** (`STORAGE_DIR`) | صور مكتبة الوسائط، والسير الذاتية، ومرفقات طلبات العروض | `scripts/backup.sh` |
| **ملف `.env`** | الأسرار (كلمة مرور قاعدة البيانات، SMTP) | يدويًا — احفظه في مدير كلمات مرور، **لا** مع النسخ الآلية |

> الكود نفسه محفوظ في Git، فلا يحتاج نسخًا احتياطيًا.

## أخذ نسخة

```bash
cd /var/www/riyada
scripts/backup.sh                      # تثبيت مباشر (يقرأ .env)
BACKUP_MODE=docker scripts/backup.sh   # Docker Compose
```

تُنشأ النسخة في `backups/<التاريخ_الوقت>/` وتحتوي:

- `db.dump` — نسخة PostgreSQL بالصيغة المضغوطة (`pg_dump --format=custom`).
- `storage.tar.gz` — الملفات المرفوعة.
- `SHA256SUMS` — بصمات للتحقق من سلامة الملفات عند الاستعادة.

الملفات تُكتب بصلاحيات المالك فقط (`umask 077`) لأنها تحتوي بيانات شخصية: السير الذاتية وبيانات التواصل.

### الخيارات

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `BACKUP_DIR` | `./backups` | مكان حفظ النسخ |
| `RETENTION_DAYS` | `14` | حذف النسخ المحلية الأقدم من هذا العدد من الأيام |
| `BACKUP_REMOTE` | — | وجهة [rclone](https://rclone.org) لنسخة خارج الخادم، مثل `r2:company-backups/riyada` |

## الجدولة اليومية

```bash
crontab -e
```

```cron
# كل يوم 3:15 فجرًا (توقيت الخادم)
15 3 * * * cd /var/www/riyada && BACKUP_MODE=docker BACKUP_REMOTE="r2:company-backups/riyada" scripts/backup.sh >> backups/backup.log 2>&1
```

احذف `BACKUP_MODE=docker` في التثبيت المباشر، وشغّل الجدولة بمستخدم `riyada`.

## النسخ خارج الخادم (مهم)

النسخة الموجودة على الخادم نفسه لا تحمي من تعطل القرص أو اختراق الخادم. اتبع قاعدة **3-2-1**: ثلاث نسخ، على وسيطين مختلفين، إحداها خارج الموقع.

1. ثبّت rclone: `sudo apt install rclone`.
2. أعدّ وجهة تخزين سحابي: `rclone config`. يدعم Amazon S3 وCloudflare R2 وBackblaze B2 وGoogle Drive وغيرها.
3. اضبط `BACKUP_REMOTE` كما في المثال أعلاه.
4. فعّل في التخزين السحابي سياسة حذف تلقائي (مثل 90 يومًا) و«إصدارات الكائنات» أو القفل ضد الحذف إن توفر.

## الاستعادة

> ⚠️ الاستعادة **تستبدل** قاعدة البيانات والملفات الحالية بالكامل.

```bash
cd /var/www/riyada
scripts/restore.sh backups/2026-10-21_031500                      # تثبيت مباشر
BACKUP_MODE=docker scripts/restore.sh backups/2026-10-21_031500   # Docker
```

ينفّذ السكربت الخطوات التالية:

1. يتحقق من البصمات (`SHA256SUMS`) ويتوقف إن كان أي ملف تالفًا.
2. يطلب كتابة `restore` للتأكيد.
3. يستعيد قاعدة البيانات في معاملة واحدة: إن فشلت لا يتغير شيء.
4. يستبدل الملفات المرفوعة.

بعد الاستعادة ادخل إلى لوحة التحكم ← **الإعدادات العامة** ← **«تحديث صفحات الموقع»** لتعرض الصفحات المحتوى المستعاد.

### الاستعادة على خادم جديد

1. انشر الموقع حسب [DEPLOYMENT.md](DEPLOYMENT.md) **دون** تشغيل `db seed`.
2. انسخ مجلد النسخة إلى الخادم الجديد (`scp -r` أو `rclone copy`).
3. شغّل `scripts/restore.sh <المجلد>`. الترحيلات المطبقة سابقًا جزء من النسخة.
4. إن كان الإصدار الجديد من الكود أحدث، شغّل الترحيلات بعد الاستعادة: `npm run db:migrate`، أو أعد تشغيل Compose فتعمل خدمة `migrate` تلقائيًا.
5. اضغط «تحديث صفحات الموقع» من اللوحة.

## اختبار النسخ دوريًا

النسخة التي لم تُجرَّب استعادتها ليست نسخة موثوقة. مرة كل ربع سنة:

- [ ] استعد آخر نسخة على خادم اختبار أو جهاز محلي.
- [ ] تأكد من فتح الصفحات وعرض الصور وتنزيل سيرة ذاتية من صندوق التوظيف.
- [ ] تأكد من تسجيل الدخول إلى اللوحة.
- [ ] سجّل التاريخ والنتيجة.
